# D0 — Documento de requerimientos

## Proyecto: Minimarket La Esquina

**Fecha:** 23 de octubre de 2026
**Autor:** Análisis de sistemas
**Versión:** 1.1

---

## 1. Problema

El minimarket La Esquina registra sus ventas manualmente y no controla adecuadamente su inventario, por lo que necesita una aplicación web interna para gestionar productos, controlar el stock y registrar ventas.

---

## 2. Usuarios y proceso actual

### 2.1 Usuarios del sistema

| Usuario | Descripción |
|---------|-------------|
| Cajero | Personal del minimarket responsable de registrar productos, actualizar el inventario y registrar las ventas del día. |

### 2.2 Proceso actual

El cajero realiza las siguientes actividades de forma manual (en cuadernos o libretas):

1. **Gestión de productos:** Anota los datos de cada producto (nombre, precio, cantidad) en un cuaderno.
2. **Control de stock:** Verifica visualmente o cuenta físicamente las unidades disponibles; no existe una alerta automática cuando un producto está por agotarse.
3. **Registro de ventas:** Anota cada venta con lápiz y papel, calcula el total a pagar mentalmente o con calculadora.
4. **Consulta del día:** Al cierre, suma manualmente los montos vendidos para conocer el total del día.

### 2.3 Dificultades actuales

- No hay control preciso del stock; es fácil cometer errores de conteo.
- No existe un mecanismo que alerte cuando un producto alcanza su stock mínimo.
- El cálculo manual del total de ventas es lento y propenso a errores.
- No hay un historial confiable de ventas para revisar el desempeño del día.
- La información del inventario no está centralizada ni es consultable rápidamente.

## 3. Requisitos funcionales

### RF1 — Registrar productos

El sistema debe permitir al cajero registrar un producto con los siguientes datos:

| Campo | Tipo | Descripción |
|-------|------|-------------|
| Código | Texto | Identificador único del producto |
| Nombre | Texto | Nombre descriptivo del producto |
| Categoría | Texto | Clasificación del producto (ej. abarrotes, lácteos, bebidas) |
| Precio | Decimal | Precio unitario de venta |
| Stock actual | Entero | Cantidad de unidades disponibles |
| Stock mínimo | Entero | Cantidad mínima antes de requerir reabastecimiento |

### RF2 — Listar productos e identificar stock bajo

El sistema debe listar todos los productos registrados y mostrar de forma destacada aquellos cuyo stock actual es menor o igual al stock mínimo, para que el cajero identifique rápidamente qué productos requieren reabastecimiento.

### RF3 — Registrar ventas

El sistema debe permitir registrar una venta indicando el producto y la cantidad vendida. Al registrar la venta, el sistema debe:

- Tomar el precio de venta vigente del producto.
- Calcular el total de la venta (precio unitario × cantidad).
- Registrar la fecha y hora de la venta.
- Descontar la cantidad vendida del stock actual del producto.

### RF4 — Consultar ventas del día

El sistema debe permitir consultar las ventas registradas durante el día actual, mostrando:

- El detalle de cada venta (producto, cantidad, total).
- El monto total acumulado vendido en el día.

---

## 4. Requisitos no funcionales

### RNF1 — Seguridad

- El sistema debe usar PDO con sentencias preparadas para prevenir la inyección SQL.
- El sistema debe usar `htmlspecialchars` para escapar la salida HTML y reducir los riesgos de XSS.

### RNF2 — Integridad de datos

- El sistema debe garantizar que el registro de una venta y el descuento de stock se realicen como una operación atómica: o ambas acciones se completan, o ninguna se aplica.
- El sistema debe validar que los datos ingresados cumplan con los tipos y restricciones definidos antes de almacenarlos.

### RNF3 — Facilidad de uso

- La interfaz debe ser clara y sencilla, accesible para usuarios sin conocimientos técnicos avanzados.
- Las acciones principales (registrar producto, registrar venta, consultar ventas) deben ser accesibles en pocos clics desde la pantalla principal.

---

## 5. Reglas de negocio

| ID | Regla | Relación con requisitos |
|----|-------|--------------------------|
| RN1 | La cantidad vendida debe ser mayor que cero. | RF3 |
| RN2 | No se permite vender más unidades que el stock disponible del producto. | RF3, RNF2 |
| RN3 | El precio de venta no puede ser negativo. | RF1, RF3 |
| RN4 | El código de cada producto debe ser único; no se permiten códigos duplicados. | RF1 |
| RN5 | Registrar la venta y descontar el stock deben realizarse como una sola operación atómica (transacción). | RF3, RNF2 |

---

## 6. Fuera de alcance

Las siguientes funcionalidades **no** forman parte de este proyecto y no deben implementarse:

- **Autenticación de usuarios:** No se requiere inicio de sesión ni gestión de credenciales.
- **Roles y permisos:** No se manejan distintos tipos de usuario con accesos diferenciados.
- **Gestión de clientes:** No se registran ni administran datos de clientes.
- **Facturación electrónica:** No se emiten comprobantes electrónicos ni se integra con SUNAT.
- **Agentes conversacionales:** No se incluyen chatbots ni asistentes de voz.
- **Despliegue público:** El sistema funciona de forma interna en el local; no se publica en internet.

---

## 7. Supuestos

A continuación se enumeran los supuestos considerados, es decir, información no establecida explícitamente en el caso pero necesaria para definir el alcance:

| ID | Supuesto |
|----|----------|
| SUPUESTO 1 | El sistema será utilizado por un único usuario (el cajero) desde un equipo dentro del local. |
| SUPUESTO 2 | El sistema se ejecutará en un entorno local (servidor web instalado en el propio equipo del minimarket). |
| SUPUESTO 3 | Una venta corresponde a un único producto con una cantidad determinada (no un carrito con múltiples productos). |
| SUPUESTO 4 | El sistema maneja una sola moneda (soles peruanos, S/). |
| SUPUESTO 5 | El stock mínimo es un valor fijo definido por el cajero al registrar el producto. |
| SUPUESTO 6 | No se requiere historial de ventas de días anteriores; la consulta de ventas cubre únicamente el día actual. |
| SUPUESTO 7 | No se requiere gestión de proveedores ni órdenes de compra. |
| SUPUESTO 8 | El sistema opera en un entorno local, por lo que las operaciones básicas no requieren conexión a internet. |
